# 01｜Anthropic 内部 10 个团队怎么用 Claude Code

**资料边界**：下列「官方报道」均据 Anthropic 2025-07-24 发布的公开报告 [How Anthropic teams use Claude Code](https://www-cdn.anthropic.com/58284b19e702b49db9302d5b6f135ad8871e7658.pdf)。页码指该 PDF 的印刷页码。**我们复刻**是独立教学方案，不代表 Anthropic 内部真实实现。报告反映其发布时实践，不表示 2026 年界面和权限机制完全相同。

## 01 数据基础设施（PDF p3–4）

**官方报道**：团队用仪表盘截图诊断 Kubernetes Pod IP 地址不足；把财务人员的自然语言步骤变成可执行的数据处理任务；用仓库文档帮助新员工理解数据依赖；每次任务结束补充说明；多个项目使用多个隔离会话。对于敏感数据，强调通过受控 MCP 方式接入。

**我们复刻**：让 AI 先读取一张脱敏故障截图、错误日志和运行手册；只生成排查顺序与建议命令；实际基础设施变更须运维人工确认。

- 输入：问题、错误日志、架构说明
- 输出：根因假设、证据、风险级别、只读排查命令、升级联系人
- 验收：根因是否有可检验证据；变更是否先审批

## 02 Claude Code 产品研发（PDF p5–6）

**官方报道**：快速原型会让 Claude 迭代编写和运行测试；核心业务逻辑则同步人工监管；利用 GitHub 集成处理部分 PR 评论，并用早期检查点回滚失败尝试。

**我们复刻**：`探索 → 计划 → 测试 → 实现 → 运行 → 审查 diff → 提交`。高风险代码必须通过人工评审。

- 输入：单个功能说明及已有测试
- 输出：变更方案、代码、单测、验证记录
- 验收：测试通过；只修改约定范围；有可回退 commit

## 03 安全工程（PDF p7–8）

**官方报道**：解释 Terraform 计划、根据栈追踪定位故障、生成 Markdown 排障手册、用测试驱动开发、用自定义命令封装重复任务。

**我们复刻**：只把已脱敏的 Terraform plan 作为数据输入，生成“新增/删除/扩大权限/成本影响”的审阅表；严禁 AI 自动执行 `terraform apply`。

- 输入：变更计划与团队安全标准
- 输出：风险清单、待确认项、回滚路径
- 验收：所有破坏性操作由有权限的人确认

## 04 推理（PDF p9–10）

**官方报道**：理解大型代码库、写覆盖边界条件的单元测试、解释陌生 ML 概念、把测试逻辑迁移到 Rust 等语言，并辅助回忆 Kubernetes 命令。

**我们复刻**：把一个 Python 小函数的约束交给 AI，让它先列边界用例，再写测试，最后移植成目标语言的等价测试。

- 验收：两种实现都通过相同测试样本；保留语义差异说明

## 05 数据科学与可视化（PDF p11–12）

**官方报道**：非前端专家借助 Claude Code 建立 React/TypeScript 分析看板；把一次性的 Notebook 升级为可复用工具；对较独立任务采用“保存状态→尝试→接受或回滚”。

**我们复刻**：虚构销售 CSV → 图表需求说明 → 静态可视化页面 → 交叉核对汇总数字。别把 5,000 行代码等同于好产品。

- 验收：看板总额能用独立算式复核；异常数据有提示

## 06 API Knowledge（PDF p13–14）

**官方报道**：把 Claude Code 当成“开始任何代码任务前的第一站”，快速找到应读文件、理解调用链、定位陌生代码中的故障，降低反复复制粘贴代码的成本。

**我们复刻**：提问“功能 A 的入口在哪里？它依赖哪些文件？给出文件路径与引用，不做修改”。再请求最小修复方案。

- 验收：文件路径真实存在；修改前先有最小复现

## 07 增长营销（PDF p15–16）

**官方报道**：通过广告表现 CSV 筛出待优化项，使用分别负责标题和描述的子 Agent 生成变体；开发 Figma 批量素材插件、Meta Ads MCP 分析能力，并保存广告假设和实验记录。报告提及文案生产耗时缩短等团队自身经验，不能直接外推给其他公司。

**我们复刻**：本项目提供 [虚构广告数据 + 确定性审计脚本](../examples/ads/README.md)，随后由两个不同职责的 Agent 起草候选文案，第三个审核环节检查字符、事实和风险。

- 验收：CTR/CPC 公式正确；生成内容不含虚假承诺；上线前人工确认
- **重要**：我们的 Python 演示只做指标审计，不调用 Meta 或广告 API。

## 08 产品设计（PDF p17–18）

**官方报道**：设计师粘贴截图生成交互原型；让 Claude 实现样式和状态变化；在设计阶段梳理错误状态；借助 GitHub 问题与工程集成处理部分修复。

**我们复刻**：截图 + 五个可见状态（加载、空、成功、失败、无权限）→ 原型 → 逐屏测试 → 设计复核。

- 验收：五种状态可触发；键盘和移动端基本可用

## 09 RL 工程（PDF p19–20）

**官方报道**：委托小中型功能、测试、故障排查和 Kubernetes 问答；采用频繁提交检查点、失败回滚；报告也指出首次尝试并非总成功，不应把自主编码当作确定性执行。

**我们复刻**：每个任务先划定 1–3 个文件、定义通过条件，再开分支实施；失败时从干净检查点重试，不无限叠加补丁。

- 验收：单次变更可回滚，跨模块修改需要审批

## 10 法务（PDF p21–22）

**官方报道**：法务人员通过 Claude Code 试做内部律师路由原型、会议状态工具、无障碍沟通原型；做法是先在 Claude.ai 讨论清楚、再用 Claude Code 小步实现，并重视 MCP 接入的隐私与合规。

**我们复刻**：只用虚构法务角色设计“输入事项→列出可能负责部门→显示人工联系方式”的工具；不做自动法律结论。

- 验收：错误路由可以修正；不输入真实客户机密

## 这 10 个案例的共同底层规律

1. **起点是可描述的业务动作，不是 Agent 数量。**
2. **上下文来自文件、截图、接口和规范；不是一段万能 Prompt。**
3. **能给 AI 的任务需要有验证途径。**
4. **把重复动作沉淀为命令、Skill 或工具。**
5. **涉及高风险变更时，保留人工批准、日志与回滚。**
